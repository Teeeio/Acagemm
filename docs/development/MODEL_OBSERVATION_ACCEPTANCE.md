# Model observation acceptance — frozen upstream contract

Date: 2026-09-13. Authority: TEAM_HANDOFF §6 scheme D and REAL_GPU_REGRESSION.
Scope of this batch: response model observation, newest real affine two-round smoke, then reduction/normalization coverage. N=20 begins only after smoke and a frozen batch success rule; Wiki follows the real regression baseline.

## Evidence semantics

Claude Code is the runtime, not necessarily the responding model. Preserved P1 raw events have system.init.model=claude-opus-5[1m], assistant.message.model=deepseek-v4-flash and result.modelUsage keys containing Claude labels. Only assistant.message.model reports the responding model in this contract. This is provider-reported metadata, not independent attestation of the remote service. Init/config/env/usage labels are retained separately and never promoted to response observation. Historical originals are never rewritten.

## Frozen DTO and pure API

New I/O-free client-runtime/model-observation.mjs exports:
- MODEL_OBSERVATION_SCHEMA_VERSION = 'operator-studio.model-observation/v1'.
- observeClaudeModel({runId, missionId, sessionId, events=[]}) returns the DTO below.
- bindModelObservation(value, {provider,runId,missionId,sessionId}) returns a deep detached valid DTO with EXACT nonblank identity matches, otherwise null. It validates complete shape and internal consistency, not just schema/status strings.
- summarizeModelObservations(observations=[], {requiredRuns=[]}={}) returns {schemaVersion, status, model, modelSource, models, requiredRunCount, observedRunCount, reasons}. requiredRuns contains {provider,runId,missionId,sessionId}; all identities must be nonblank, unique by provider/mission/run. Missing/malformed/foreign/conflicting evidence makes status unknown/conflict, never observed. Repeated identical observations for one binding do not add a run; contradictory duplicates fail closed. Empty requiredRuns is unknown.

DTO (all fields required):
{schemaVersion, provider:'claude-code', runId, missionId, sessionId,
 status:'observed'|'unknown'|'conflict', model:string|null,
 source:'assistant.message.model'|null, models:string[],
 configuredModels:string[], usageModels:string[],
 observations:[{eventIndex:nonnegative integer,sessionId:string,model:string}],
 reasons:string[]}.
Arrays of model strings are trimmed, unique and sorted. observations contain only metadata, never text/thinking/tools/secrets. Missing/blank/unknown/null/undefined/<synthetic> model labels are not valid observations (case-insensitive sentinels). Identity strings must be nonblank; no guessing from other runs or environment.

For observeClaudeModel:
1. Read all actual assistant.message.model metadata before telemetry filtering (including thinking-only events), with explicit matching event.session_id. An absent event.session_id or mismatch invalidates completeness; retain a reason. A foreign session must never replace current session identity.
2. All assistant events must report valid model metadata. Zero assistant responses or any missing/invalid model/session yields unknown unless conflicting concrete models/sessions make conflict.
3. Exactly one valid response model across complete matching responses => observed, model that value, source assistant.message.model. Multiple concrete models => conflict/model null/source null. Init and usage disagreement with responses is diagnostic only and is not a response conflict.
4. configuredModels from system.init.model; usageModels from result.modelUsage keys. Neither supplies observations. Other event fields named model or text containing model are ignored.
5. Every run begins unknown; resumeThreadId alone is not observation. Current stream metadata only. Preserve model metadata through normal lines and unterminated final JSON line, logical completion and physical close, cancellation/error; no private thinking content persisted.
6. bind rejects inconsistent observed/model/models/source/observations, malformed index/string/arrays/schema/status and exact provider/mission/run/session mismatch. unknown/conflict may be valid DTOs but never establish comparability.
7. Summary observed only if every required run has valid observed DTO and all report the same response model; modelSource='observed' then, otherwise 'unknown'. Different models across valid runs => conflict. No identities/timestamps in stable fingerprint.

## Producer / production ownership

Claude adapter persists record.modelObservation with run/mission/session binding, starting unknown. Session is learned from the current raw stream; resume hint is not observed. agent-runtime projects only exact current-run/provider/mission/session-bound observation to state.agent.modelObservation, including cancellation settlement branches; missing/new/foreign data clears stale observation. Reset/archive preserves the bound value as runHistory[].modelObservation; new runs do not inherit old observation. Metadata changes must trigger changed=true even without event-count/status change. Existing workflow/Gate/resource-release behavior is unchanged. Production does not consume model identity as a control gate.

## Acceptance driver / ledger ownership

Driver maintains required run identities across every configured Mission, all started iteration/recovery/continuation runs (including failed and zero-candidate runs), not just successful candidate source IDs. Observe state and retained current-attempt bridge run records; retain final per-run DTOs and requiredRuns as top-level modelObservations/modelObservationRequiredRuns in both attempt and summary. Restrict reads to current runRoot and expected Mission IDs; safe filenames, no stale other-directory search. At finalization use physical final records where available; do not lose records between polls, on timeout or early failure. No candidates/workflow advancement injected.

Persist modelObservationSummary at top level. final config.provider contains model, modelSource, modelObservationStatus, modelObservationVersion derived from that summary. Keep declaredModel and declaredModelSource separately as requested configuration; no env upgrade. buildConfigFingerprint requires observed status, schema version and modelSource='observed' for model eligibility (CLI version still uses existing actual probe sources). Per-run observation evidence stays outside config hash. Same model and same config but different run/session IDs => identical fingerprint.

Ledger independently recomputes model summary from required runs + DTOs, rejects missing/foreign/conflicting/malformed evidence or disagreement between attempt/summary/config claims for comparability. It never upgrades outcome or drops an attempt. Missing observations make N20 ineligible even if a forged config says observed. Legacy records remain counted, non-comparable; no backfill. Existing outcome/release/duplicate and full_success vs budget_terminal semantics remain intact.

## Teardown evidence clarification (before consumer implementation)

Root inspection found stopMission returns HTTP 202 for unconfirmed release; the existing driver's generic request helper accepts any 2xx, ignores the release response and kills the Runtime in finally. The consumer's final-record collection must therefore preserve the existing teardown call's response and verify the current Mission's resourceRelease before treating cleanup as confirmed. Retain a per-family stop receipt/final state. On error/timeout, stop the still-owned current Mission through this same production API before terminating the Runtime, retaining the original failure and cleanup/release details. Only bounded read-only observation may follow an unconfirmed stop; do not start a new Mission while resources are pending/quarantined. An unknown/unconfirmed release cannot produce full_success. Teardown stop is separate from workflowWritesAfterStart; it must never advance the loop or inject a candidate. Read actual final bridge records after stop so a third/recovery run begun between polls is not lost. No provider/GPU execution in worker verification; Root independently checks these receipts during live acceptance.

## Frozen consumer helper acceptance (upstream review clarification)

The first consumer candidate passed B but Root executed its actual collector helpers in an isolated VM and reproduced three false observations: an earlier observed DTO masks a later unknown final record; the DTO supplies its own expected session instead of the record session; an unreadable second run file disappears. The driver also still ignores the stop receipt. Extract the following I/O-free helpers into the existing scripts/shared-gpu-acceptance.mjs so independent tests can exercise the actual consumer behavior; the driver must call these public helpers, not retain a separate reader.

1. collectModelObservationEvidence({provider, missionIds=[], knownRuns=[], records=[]}) -> {observations, requiredRuns, summary, unboundRuns}. knownRuns are independently observed start identities {provider,runId,missionId,sessionId?}, with missing Mission/session allowed only as unknown pending final-record evidence. records are the FINAL filesystem read results [{fileName,record,error}], where record is parsed JSON or null and error is a nonblank read/parse error or null. Safe filenames are single basenames ending .json, with an alphanumeric first character and no separators. Validate filename/runId, expected provider, expected Mission and independent record.sessionId / compatible record.threadId (if both nonblank they must agree). A DTO's own fields never supply expected identities. Unknown fields may only be completed from this current-attempt actual record; concrete conflicts cannot be overwritten. Known starts dedupe by provider/run identity, not success, and every known start remains required even when its final record is absent/malformed or session is blank. A new safe run file with unreadable/invalid content remains an unbound required record and makes the summary non-observed; do not silently skip it. Concrete unrelated foreign-Mission files may be ignored only when they are not referenced by a known start. Duplicate final records with conflicting content fail closed. Final records are authoritative for evidence: earlier snapshot DTOs are not evidence fallbacks and no ranking can prefer observed over a later unknown/conflict/missing state. Multiple families and runs must retain their original Mission binding. Use bindModelObservation + summarizeModelObservations as the DTO authority. unboundRuns must retain run identity and a reason. No file read, provider, time or environment access inside this helper.

2. evaluateMissionStopReceipt({missionId, receipt}) -> {confirmed:boolean, reasons:string[]}. receipt is the real HTTP body {state}, or a later readonly {state} observation. Require exact state.activeMissionId, missionPaused===true, stopped loop intent, and explicit state.workflowRecovery.resourceRelease confirmed true/status confirmed with a resources array. Every listed resource must explicitly confirm release and have no pending/unconfirmed/quarantined/blocked flags. If a current Agent run exists require its same-Mission explicit release proof too (reuse resourceReleaseEvidence); reject current resource barriers via the existing cancellation contract. Absent/malformed/foreign/pending release is false even when HTTP was 2xx or Agent status is terminal. It performs no cancellation or state mutation. The actual driver must retain the stop body/final state and evaluate it on both success and error/timeout before killing its Runtime. A 202 may only become confirmed after a bounded readonly observation proves release; never by elapsed time or a terminal status alone.

3. Ledger validation must also reject a malformed declared modelObservationSummary (required fields and valid reasons array; observed reasons empty). When duplicate attempt aliases have the same config/outcome but contradictory per-run model proof, treat them as a duplicate conflict, not a harmless alias of the first good record. ### Review clarification: conflict order, final reads and cleanup reachability

The first 48-case consumer pack omitted some already-required boundaries. Root ran the second candidate directly and reproduced false observed summaries for conflicting duplicate records in the reverse order, a new parsed-empty record, a new expected-Mission record with a foreign provider, and conflicting concrete known-start identities. Conflicting final records and concrete known-start identities must fail closed in either order; only semantically identical duplicates dedupe. Missing/invalid Mission identity is not proof that a new safe file belongs to an unrelated Mission. It remains required/unbound. A concrete foreign-Mission file may be excluded only when no known start references it.

The driver's final sweep must refresh physical evidence, not keep an old successful read after a file disappears or directory enumeration fails. Preserve discovered run filenames/identities as required while marking final read errors; never retain the old DTO as fallback. Helpers used by error/timeout cleanup must be lexically available to `finally`. Stop evidence retains the original HTTP body plus any later read-only proving state; do not replace the initial receipt with the last poll. Observe independent start identities in stop/final states too. A request failure and its cleanup failure remain separately visible.

A proving stop has `iterationStats.loopStatus === 'stopped'`; paused/idle by themselves do not establish stopped intent. Check the existing `resourceReleaseBarrier` across Agent, research, materializer and test resources in addition to the explicit Mission release and current-Agent proof. An idle placeholder Agent with no run does not invent a current execution resource or require a fabricated Agent release. A nonblank current run still requires the exact same-Mission explicit release. Independent tests extend the existing collector file before consumer retry, preserving its original 48 cases.

Accepted serialization detail: unresolved Mission/session fields in output `requiredRuns` use the explicit `<unresolved-mission>` / `<unresolved-session>` markers so the pure summary retains the required-run denominator. These markers are added only when serializing required identities, after binding has already used the independently observed raw identity; they never fill the expected identity passed to `bindModelObservation` or supply an observation. The unbound entry retains the missing identity and reason. An empty, explicitly confirmed Mission resource list is also valid when an already-terminal current Agent separately proves its release; the list describes resources involved in the stop, not a requirement to invent a pending resource.
