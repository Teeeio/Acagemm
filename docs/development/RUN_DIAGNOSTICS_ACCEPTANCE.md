## Single route and ownership

Add diagnostics to the existing Claude client run JSON, returned by `readRun`.
Do not add a workflow, service, persisted Mission schema or model-observation DTO.
Agent Runtime supplies diagnostic context through the existing provider cancel
port: `cancel(runId, context?)`. Its engine already forwards positional arguments.
Only Claude receives this extra argument; other provider calls retain their shape.
The client owns run-file persistence; Runtime owns trigger/budget interpretation.

Implementation A owns `claude-client.mjs` and the client-runtime README.
Implementation B owns `agent-runtime.mjs` and its companion MD.
Independent tests own the new test, test README, npm script and release registration.
This file is immutable acceptance input and none of those authors may edit it.

## D1: exact bounded run record

Every new Claude run has `diagnostics` with exactly these keys:

```json
{
  "schemaVersion": "operator-studio.agent-run-diagnostics/v1",
  "provider": "claude-code",
  "runId": "current exact run ID",
  "missionId": "current exact mission ID",
  "stdout": {"chunks": 0, "bytes": 0, "firstAt": null, "lastAt": null},
  "stderr": {"chunks": 0, "bytes": 0, "firstAt": null, "lastAt": null},
  "events": {"systemInit": 0, "thinkingTokens": 0, "assistant": 0, "result": 0, "other": 0, "invalidJson": 0},
  "firstModelObservedAt": null,
  "cancellation": null,
  "close": null
}
```

Times are actual UTC ISO timestamps at the client boundary, never reconstructed
from event content. Counts are nonnegative safe integers, saturating at
Number.MAX_SAFE_INTEGER; event keys never come from arbitrary provider strings.
Count every nonempty stdout/stderr data chunk and its byte length. Empty chunks
are no-ops. First/last times are per stream. Do not change existing lastActivityAt
or stall semantics. Count each nonblank JSONL line exactly once, including the
unterminated final line at close. A parsed object is classified by the existing
event type/subtype; valid primitives/arrays and unknown types are `other`.
Invalid nonblank JSON increments `invalidJson`. Count telemetry before filtering.

`firstModelObservedAt` is set once, only when the existing model-observation
authority first produces status `observed` for this run. Init/usage/configured
labels never set it. Later conflict does not erase the historical first time and
does not make the current DTO comparable. Diagnostics never change the DTO.

`close` is null until the real child `close` callback, then exactly
`{at, exitCode, signal}`: exitCode is the integer callback value or null; signal is
one of the fixed conventional Node signal names, otherwise null. No invented
success code. Close is a child lifecycle fact, not a new process-tree release proof.

## D2: cancellation context and persistence

For a live owned child, the first actual `cancel` call sets `cancellation` to
`{requestedAt, context}` before waiting on termination. It must become durable
while termination remains pending, via the existing serialized atomic run writer.
Do not await a diagnostic-only write before starting termination. Repeat calls
must not overwrite the first requestedAt/context. Calling cancel after the child
is gone does not fabricate a request. Older persisted records without diagnostics
remain readable and are not backfilled.

Optional context has exactly these keys:
`schemaVersion` = `operator-studio.cancellation-context/v1`,
`runId`, `missionId`, `role`, `trigger`, `triggeredAt`, `budgetMs`, `elapsedMs`,
`stallTimeoutMs`, `idleMs`.
Role: `main`, `research`, `materializer`.
Trigger: `explicit_cancel`, `budget_exceeded`, `stall_timeout`,
`budget_and_stall`, `logical_completion`, `prior_cancel_requested`,
`terminal_unreleased`, `release_pending`.
Budget and elapsed/idle values are finite nonnegative numbers or null; timeout
values are finite positive numbers or null. Unknown is null, never guessed zero.
triggeredAt is a valid ISO timestamp generated by Runtime at actual provider
invocation. Exact nonblank run and Mission identities must match the client's
record. Invalid schema/identity/enum/time/numeric data yields context=null without
preventing cancellation. Copy only listed keys (extra keys are dropped), so raw
text, credentials, paths, prompt, stderr and thinking cannot enter diagnostics.
Direct legacy cancel(runId) legitimately produces context=null.

All diagnostic fields must be durably final at close after earlier queued writes.
New stderr-only activity and cancellation must be observable before close (reuse
the existing bounded/throttled persistence scheme); no new unbounded event arrays
or timers. The existing raw event/error behavior is outside this change.

## D3: Runtime producers, without policy changes

The first actual call through requestCancellation supplies detached scalars only.
Reuse the exact booleans/effective budgets from the existing branch; do not
recompute policy with different fallback or precedence. Main expiry records
budget_and_stall if both booleans are true, otherwise the true trigger. Materializer
and research expiry record budget_exceeded. Explicit cancelRun records
explicit_cancel for its selected role. On automatic settlement without expiry,
choose logical_completion, then prior_cancel_requested, then terminal_unreleased,
then release_pending, in that order according to the existing conditions.
The early already-released return makes no cancellation request/context.

Pass current role/run/Mission identity (role missionId, or current active Mission
when absent). For main automatic expiry use the effective main budget, elapsed,
main stall timeout and measured idle at this branch. For research/materializer use
their effective existing budget/elapsed; stall values null. Explicit cancellation
may leave timing/budget values null because it does not evaluate expiry.

Single-flight reuse must not call the provider again or generate replacement
context. Deadline, retry limit, pending/quarantine and late-result behavior remain
unchanged. Context must not capture a mutable state reference. No new cancellation
path, new retry, relaxed release barrier or model-label fallback is permitted.

## Independent acceptance matrix

- T1: new run defaults and two simultaneous runs keep separate identities/counts.
- T2: init + thinking_tokens then cancel/close with no assistant remains unknown;
  telemetry counts survive filtering; no thinking/body bytes in diagnostics.
- T3: thinking-only assistant and an unterminated assistant tail count once and
  set firstModelObservedAt through the existing authority. Init/usage alone do not.
- T4: stdout/stderr byte counters, first/last times, blank/invalid/unknown event
  classes and fixed key count; final data and close receipt survive JSON reload.
- T5: cancel with termination promise held pending: cancellation is durable while
  close is null; repeat/invalid/foreign context cannot replace a valid first one;
  missing context and after-close cancellation retain truthful null behavior.
- T6: actual createAgentRuntime.projectState budget-only, stall-only and both
  branches deliver correct context; no premature release or candidate admission.
- T7: actual cancelRun main/research/materializer produces explicit_cancel;
  automatic research/materializer budgets produce their correct role/context.
- T8: held provider cancel crosses caller deadline, repeated projectState reuses
  the same provider call, finite retry exhaustion remains blocked; late completion
  does not mutate an earlier snapshot; subsequent release projection converges.
- T9: existing model-observation, timeout recovery, cancellation liveness and
  Runtime tests remain valid; no test weakens old invariants to accept this change.

Tests use real client/Runtime entry points with injected child/provider doubles,
bounded synchronization and isolated local files, no live CLI/model/GPU. Existing
tests may be reused for established properties; new assertions target diagnostics.
Author phase only syntax/available existing targeted tests; execute the new test
against the combined candidate, never claim it passed against missing producers.
Register `test:agent-run-diagnostics` in package.json and the existing release list.
Final combination runs that test and existing non-hardware robustness wrapper
(which itself runs verify:local-c500-release), plus cancellation liveness and
timeout recovery if not already covered. Root independently reviews exact tuples.

## Stop conditions and real continuation

Return decision_request on a missing interface, policy contradiction, repeated
failure or required out-of-scope edit. No new dependency, architecture, agents or
unrelated refactor. No production/GPU run by implementation authors.
After integration and required gates, Root freezes a new source and uses the
existing real two-round shared-GPU production harness. Inspect run diagnostics
alongside model observation and resource release. Only then decide a fresh exact
N20 batch; never replace an old unknown with an extra run or call diagnostics a fix
for unproven provider failure. This is a diagnostic extension, not a stability claim.
