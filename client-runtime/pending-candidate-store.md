# Pending candidate storage adapter (W2)

The frozen manifest optionally retains the normalized Mission `targetProfile`.
Its manifest digest covers the profile, which follows the existing new-attempt
copy path. Legacy manifests without this field remain valid. It is optimization
intent only, not an execution receipt or publication permission.

`verifyWorkspace(pending,{workspace,diff})` verifies the original immutable bundle,
trusted workspace path, complete diff and all frozen/declared/known-language source
bytes. It rejects new untracked files, altered dependencies, unsafe file links or
missing sources. It reads twice, never restores files, and returns a binding for
explicit feedback. The application must obtain `diff` with read-only capture.

`pending-candidate-store.mjs` stores a bounded, immutable snapshot of an **untested**
candidate. It does not prepare an execution package, probe an environment, start a
queue task, issue a verdict or grant publication authority. `awaiting_backend`
always means the candidate still needs backend preparation and real testing.

## Public port and composition

```js
const store = createPendingCandidateStore({ artifactDirForMission, now });
const pendingValidation = await store.freeze({ state, mission, candidate, workspace, diff });
const bundle = await store.read(pendingValidation);
```

`artifactDirForMission(missionId)` must resolve the **authoritative** artifact
directory from the application's saved Mission. It may be async. Production
composition wraps the existing three-argument path helper by looking up that
Mission's `repository` and `projectRoot` from read-only state. Never derive this
root from a DTO path or from the bundle being read. This permits restart reads
without in-memory registrations, while retaining the three-layer Project root.
The optional `now()` clock defaults to a Date; it only timestamps a new bundle.

The existing apply-patch journal owns the `runEffect` call and persists the
returned DTO to `iterationStats.pendingValidation`. This adapter never mutates
Runtime state. `workspace` must come from the production managed-workspace port,
be absolute, and match the complete `workspaceManager.captureDiff` result's
`workspace`. Caller serialization must keep Agent writes stopped during capture
and freezing. The adapter verifies file boundaries and two matching source reads;
it does not run Git, independently prove workspace ownership, or recapture a diff.

Freeze requires a matching active Mission, a candidate/source run, the existing
valid round budget, and a complete frozen Semantic Snapshot whose canonical digest
recomputes correctly. The current test matrix/testSpec must agree with the frozen
semantic testSpec. Expired/completed clocks are copied without renewal; this is
storage, not start admission. Missing facts are errors, never synthesized evidence.
Candidate `sourceRunId` wins over the current Agent's run; only when absent is the
current Agent run used. Explicit candidate Mission/round/patch identities cannot
conflict with the captured context.

## Source selection

Selection follows the existing `local-server.readMissionRunPy` and benchmark
package preparation read set: prefer `run.py`, otherwise `operator/run.py`; include
every present path in the fixed Profile `candidateContract.allowedFiles`, or the
canonical language adapter's `allowedFiles` when no Profile overrides it. It is
independent of `diff.changedFiles`; unchanged bridges, native sources, bindings,
build files and fixed Profile references are preserved.

Additionally freeze every explicit `sourceFiles` path in `mission.sourceFiles`,
`mission.sourcePolicy.sourceFiles` (the persisted generic intake location),
`mission.implementation.sourceFiles`, and `candidate.sourceFiles`. Entries may
be strings or `{path, role, ...}` objects. These declarations are mandatory when
present: a missing declared file is rejected. Paths are explicit portable relative
paths, not globs; the adapter does not infer imports or install dependencies.
Package consumers must use this frozen file set instead of re-reading a later
Workspace. The existing preparer itself is not modified in W2.

Independent baseline bytes come exclusively from `state.baseline.oracleRunPy`,
falling back to `state.baseline.materializer.result.runPy`. They are stored in a
separate baseline namespace as `oracle.py`. A declared Workspace `oracle.py` is
also preserved as a source file, but never substitutes for this independent
baseline. No oracle, correctness or performance result is generated by freezing.

## Exact return/reference structure

`freeze` returns only this JSON DTO (the existing caller persists it):

```js
{
  schemaVersion: 'operator-studio.pending-candidate/v1',
  status: 'awaiting_backend',
  missionId, candidateId, sourceRunId, roundId,
  patchDigest, manifestDigest, artifactPath, createdAt,
  files: [{ path, digest, size }],
  baselineDigest, semanticDigest, testSpecDigest
}
```

The artifact is one canonical JSON file named
`pending-candidate-<64 lowercase SHA-256 hex digits>.json` directly inside the
resolved Mission artifact directory. Candidate IDs never form filesystem paths.

`read` returns the **entire validated JSON bundle**, suitable for a JSON GET
response; it does not return decoded Buffers or reopen the Workspace:

```js
{
  schemaVersion: 'operator-studio.pending-candidate-bundle/v1',
  manifestDigest, createdAt, bundleDigest,
  manifest: {
    schemaVersion: 'operator-studio.pending-candidate/v1',
    status: 'awaiting_backend',
    missionId, candidateId, sourceRunId, roundId,
    patchDigest, baselineDigest, semanticDigest, testSpecDigest,
    workspace, entrypoint,
    mission: {
      id, repository, projectRoot, hardware, objective, metric,
      implementation, operatorProfile, sourcePolicy, sourceFiles
    },
    candidate,             // Complete JSON candidate, with sourceRunId/patchDigest bound.
    diff,                  // Complete captureDiff object, including original patch text.
    roundBudget,           // Original persisted object; never renewed.
    semanticSnapshot,      // Complete frozen snapshot.
    testMatrix, testSpec,   // Complete current matrix and its exact testSpec.
    files: [{ path, digest, size }],
    baseline: {
      source: 'baseline.oracleRunPy', // or 'baseline.materializer.result.runPy'
      file: { path: 'oracle.py', digest, size }
    }
  },
  files: [{ path, digest, size, encoding: 'base64', content }],
  baseline: { path: 'oracle.py', digest, size, encoding: 'base64', content }
}
```

Byte sizes are decoded byte lengths. Binary dependency files remain byte-exact.
`manifestDigest = contentDigest(canonicalJson({manifest, files, baseline}))` binds
all source/baseline bytes, candidate/source/round identity, full diff and all
frozen contracts. `bundleDigest` hashes the whole envelope except itself, including
the creation time. Per-file digests and `baselineDigest` hash original bytes;
`patchDigest` hashes original diff text. Semantic/testSpec digests reuse the
canonical semantic contract functions, without trusting stored self-reports.

Creation time is outside the content address so retries with a later clock reuse
the first fully validated bundle and timestamp. Every other payload byte must
match. No existing file is overwritten, repaired or deleted. Single-process
transactions serialize by artifact filename, including across store instances.
Exclusive file creation also refuses competing files. A crash can leave a partial
file; future reads/freezes reject it rather than claiming a committed snapshot.

## Safety, limits and errors

Read resolves the original directory through the trusted Mission port, requires
the exact digest-derived filename, reads only a bounded single-link regular file,
and revalidates canonical bytes, every hash, identity and DTO field. It performs
no mkdir, repair, mutation, hardware/environment inspection or execution.
Parent symlinks/junctions, file symlinks/hardlinks, special files, path escapes,
case collisions and reserved runtime paths are refused. Workspace and artifact
directories cannot overlap. As with package storage, this is a private store with
one owning Runtime, not an OS sandbox against hostile concurrent directory swaps.
Hash integrity is not a signature or independent execution evidence.

Limits exported as `PENDING_CANDIDATE_LIMITS`: 256 Workspace files; **4 MiB combined
source plus baseline bytes**; 2 MiB original patch text; 512 KiB metadata excluding
patch text; **8 MiB complete canonical JSON bundle**. Main GET composition should
permit an 8 MiB JSON response (plus its normal small transport envelope), without
raising request-body limits or truncating the export.

All failures are typed `PENDING_CANDIDATE_*`, non-retryable automatically:

| Suffix | Meaning |
|---|---|
| `IDENTITY_INVALID` | Mission/candidate/source/round/diff or persisted reference mismatch |
| `SEMANTIC_INVALID` | Missing/unfrozen/corrupt semantics or conflicting testSpec |
| `BASELINE_REQUIRED` | Independent baseline bytes missing |
| `LANGUAGE_UNSUPPORTED` | Unknown/conflicting language contract |
| `PATH_INVALID` | Unsafe source path or artifact outside the expected directory/name |
| `STORAGE_UNSAFE` | Link, special file, unsafe ancestor or Workspace/artifact overlap |
| `NOT_FOUND` | Required source, directory or bundle absent |
| `SOURCE_CHANGED` | File/read identity or double-read source contents drifted |
| `LIMIT_EXCEEDED` | File count or byte bound exceeded (HTTP 413) |
| `CORRUPT` | Malformed/noncanonical bundle or broken content/envelope digest |
| `CONFLICT` | Another valid payload occupies the immutable destination |
| `INVALID` | Invalid JSON metadata/clock or other adapter I/O failure |

Other errors use HTTP 409. No recursive deletion exists in the adapter.

## Verification

`node tests/pending-candidate-store-test.mjs` uses real temporary files and reports
each case's duration. It covers unchanged dependencies/native language files,
independent oracle precedence, all frozen identities, later Workspace drift,
restart/idempotent/concurrent access, tampering and valid foreign replacement,
path/link/hardlink/size rejection, read-only missing-file behavior and the legacy
entrypoint/Profile read set. It invokes neither models nor GPU/runtime processes.
# Frozen baseline provenance

New manifests include `baseline.metadata` (kind, source, source policy and original
materializer metadata/digest), plus Mission operator/source context. It is covered
by the immutable manifest hash. Oracle bytes remain independent; candidate source
files cannot substitute. Old bundles keep their existing format and remain readable.
Test admission rejects missing provenance instead of borrowing a later baseline.

## Intake review digest compatibility

The pure bundle boundary accepts the intake reviewer's 64 lowercase hexadecimal SHA-256 value and canonical sha256:-prefixed form, normalizing only this representation. Source roles, path/link restrictions, review identity, frozen semantics and full manifest verification remain mandatory. A malformed digest is still rejected.
