# Frozen business acceptance policy

`business-acceptance.mjs` is a pure domain contract. It imports only the runner alias contract. The optional `testSpec.acceptancePolicy` is part of the existing testSpec/semantic digest; there is no separate task or policy identity. Absence keeps legacy task semantics without migration.

Schema: `operator-studio.acceptance-policy/v1`, `protectedProfiles` (unique subset of requiredProfiles including primary), `maxRegressionFraction` in [0,1), `successTarget` with mode strict-improvement, relative-improvement (fraction value), or latency-limit (microsecond value). New generic forms show protection of all declared profiles with zero permitted regression. The saved draft retains explicit policy choices; old forms without the choice remain legacy until explicitly changed.

The Gate reads frozen snapshot testSpec when present and the existing semantic binding verifies the execution matrix digest. Every required benchmark profile and complete correctness coverage remain required. Baseline evidence must bind the same frozen testSpec digest, so profile labels cannot conceal changed shapes, tolerances or measurement requirements. Protected profiles must each match an actual baseline measurement by profile, runner and unit and have positive settled values. The first candidate is not exempt. Old baseline evidence without full measurements or that testSpec binding is unknown and requires a new baseline measurement; values are never inferred from a primary label.

Correctness usability, permission to replace best, and meeting the success target are distinct projections. Strict primary improvement is necessary to replace best; a tie is not optimization. A candidate may be retained as progress below a numeric target only when the protected matrix, existing evidence and semantic rules pass. The Gate's eligibleAsBest is not the fact of adoption. UI and exports must use persisted currentBest and its bound decision for that fact. Existing fixed-profile suite rules remain additional restrictions.

Inputs have no effects. Output issues and per-profile comparisons explain missing evidence and regressions. This contract neither executes tests nor grants publication. Baseline evidence retains the full actual measurement matrix, including settling status. Validation rejects malformed explicit policy rather than silently defaulting it.
