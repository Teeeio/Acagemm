# Durable Claude Job loss retirement

`createClaudeJobLossRetirement` is a filesystem adapter for the narrowly approved native `claude.exe` iteration with a durable Windows Job identity but no terminal receipt. It does not broaden legacy retirement eligibility. Inputs pin original raw-byte digest, Mission/run/session/workspace, Job/PID/creation time and supervisor/owner, exact lease bytes/experiment identity, and explicit operator confirmation. Trusted application ports supply the actual current experiment queue and all other current resources. Every task in that queue, including foreign Mission tasks, must have terminal status and confirmed release. Historical sibling queues are not migrated into an explicitly rooted experiment.

The commit claims the existing harness coordination file exclusively, repeats two fresh ordered kernel and complete transport observations, and rechecks raw inputs. It archives the original run bytes, fsyncs immutable local and checkout-wide permanent fences, archives exact lease bytes, removes only that still-matching logical lease, then fsyncs the final `operator-studio.execution-retirement/v1` receipt. An interrupted pending fence retains no-resume/candidate barriers; an exact retry reconciles the immutable archive and pending fence. Existing final receipts are idempotent only for the same authorization and inputs. Malformed or changed artifacts fail closed.

The census additionally binds pinned supervisor/owner/harness PIDs to the verified target creation-time upper bound: the original ancestors necessarily existed before target startup. A new process with a later creation time is recorded separately as `reusedPinnedProcesses`, not killed or mistaken for the old ancestor. Unknown/earlier creation times remain matching barriers. Every native Claude transport and every exact run/session/workspace/Job token still matches regardless of PID reuse. The kernel target PID/creation-time conflict still blocks; this distinction does not prove historical physical release. Calls without the optional public `pinnedCreatedNoLaterThan` census input retain the original PID-only matching behavior.

Original run JSON/JSONL and startup/stream artifacts are never rewritten. Original whole-tree exit, remote outcome and remote cost stay unknown; `releaseConfirmed=false` remains. Only the exact operational lease is retired. Read projections use the frozen original, quarantine later raw changes as audit data, and suppress all old events. Global fences reject old Mission/run/session/workspace before auth or provider startup; the harness also rejects the old experiment even with `--recover`. Canonical state stores the receipt via the existing empty-body production Mission retirement route, pauses the old Mission, and preserves histories, budgets and best/candidate evidence. Normal projection can restore a lost canonical state commit from the trusted sidecar before reading events or admitting candidates.

The composition root accepts a host-only `OPERATOR_RETIREMENT_ONLY_CONFIG` file with schema `operator-studio.job-loss-retirement-config/v1`, pinned existing data/runtime roots, exact expected identity and approval/lease inputs. `OPERATOR_AUTO_TICK=0` is mandatory. Maintenance uses the original frozen experiment, original runtime descriptor and a separate PID artifact. It permits only health/state/queue reads and the exact retirement POST; every other API action is forbidden. It starts no auth probes, provider or GPU. This does not admit live optimization from an unsuitable tool host: a new independently supervised runtime still needs an actual positive CPU preflight.

Public consumers: Claude client, production composition root/application orchestration, and `scripts/local-nvidia-harness/execution-lease.mjs` through `assertHarnessIdentityNotRetired`. Domain rules use only the pure cancellation-contract receipt predicates. No ACL, AppContainer, tolerance, fixed matrix, retry budget, queue verdict, or publication rules change.
